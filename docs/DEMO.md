# Prompt Rewriter case study

The 68-second, silent, caption-first video uses the existing `prompt-rewriter-capture-v2.mp4`
source. It is a new edit, not a newly recorded application session. The source is excluded from
Git and was inspected for credentials, browser data and other personal content before editing.
Only a synthetic Python-learning request and its returned prompt are shown.

The continuous source segment is cropped to the upper-left 1220 × 350 pixels and scaled for
readability. All request/result text remains visible. The original repository README and scripts
identify the run as local Ollama. The footage does not expose a provider log, so that attribution
is documented provenance rather than independently visible provider telemetry. No new model request
was made while producing this edit. No safety-cancellation scene was staged or fabricated.

There is no voice narration or music. All explanation is readable on screen. A voice recording
and a new cancellation take could be added in a future capture session.

## Rebuild locally

Prerequisites: existing Python with Pillow, FFmpeg, FFprobe, Windows Segoe UI fonts, and the
original source recording. The renderer does not install software or access providers.

From the repository directory:

```powershell
python scripts/build_case_study.py `
  --source 'C:\path\to\prompt-rewriter-capture-v2.mp4' `
  --repo . `
  --workdir .demo-case-study
```

The source must match the recording used here: 1424 × 694, 30 fps nominal, approximately 37.67 s.
Expected SHA-256: `2bd15e5cd09b7537292804a63e20e2326573f69bb498c7dd129e5ed0c1180383`.
Check the current `provenance.json` generated by the review renderer before reusing this hash.
The renderer creates a manifest and a continuous take in the work directory, and the case study
and poster under `assets/`. It preserves the original source file.

## Code behind the explanation

- `daemon.py`: one worker and overlapping-trigger handling.
- `workflow.py`: snapshot, capture, input limits, accessibility fallback, repeated state checks,
  paste and conditional restoration.
- `providers/router.py`: configured order, one attempt per provider, failure isolation.
- `providers/*_provider.py` and `prompts.py`: strict five-field response validation and local rendering.
- `tests/test_workflow.py`: focus, clipboard and target-text changes, among other controlled cases.

The case study is not a performance benchmark, proof of factual correctness, or compatibility test
for arbitrary apps. The checks cannot make desktop automation atomic.
